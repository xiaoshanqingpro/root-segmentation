# 根系扫描图像分割

把根系**扫描图**里的干扰（水渍、阴影、反光、扫描仪黑边）去掉，输出与原图同分辨率的干净根图，
供 WinRHIZO 测量**根总长 / 投影面积 / 表面积 / 根体积 / 平均直径 / 根尖数**。

输入是 600 dpi、约 4962×7019 或 7019×4962 的扫描件，根通常只占画幅的 1%–2%
（最低 0.01%，最高 5.5%），且颜色跨度极大（根灰度从 62 的近黑根到 163 的极淡根）。
两条技术路线都已在真实数据上跑通：

| 路线 | 实现 | 产出 | 定位 |
|---|---|---|---|
| 经典规则管线 | `code/rootseg_common.py` | 纯黑白二值图，**437 张** | 迭代 10+ 轮后到顶，现作为基线与预标注兜底 |
| U-Net 语义分割 | `code/43_train_unet.py` → `code/44_infer_unet.py` | 保留原色的白底图，**331 张** | 当前主线 |

> **本仓库不含图像数据。** 全部数据约 67 GB，光是 768 张未压缩 600 dpi TIFF 就占 58 GB
> （CV 二值图单张约 100 MB），远超 GitHub 限制，仍留在本地磁盘，不入版本库。
> 仓库只收脚本、文档与纯文本产物。

## 数据资产

三个数据集，全部为 600 dpi 扫描件（杉阔混交林有 14 张源图是 300 dpi，已重采样）。

| 数据集 | 原图 | 朝向 / 尺寸 | CV 机器图 | U-Net 机器图 | 说明 |
|---|---|---|---|---|---|
| 数据集1 | 108 | 纵向 4962×7019 | 106 | 26 | 排除 2 张非样本件（透射背光、叶片） |
| 数据集2 | 210 | 横向 7019×4962 | 180 | 154 | 含 13 张 tif；按 MD5 去重后 180 张，源目录只读 |
| 杉阔混交林 | 151 | 纵横混合 | 151 | 151 | 含 14 张 300 dpi 源图 |

合计 **469 张原图 → 437 张 CV 机器图（42.5 GB）+ 331 张 U-Net 机器图（15.2 GB）**。
CV 端的缺口来自去重与非样本件排除，U-Net 端的缺口见"已知问题"第 2 条。

**真值 / 测试区**：人工精修图（`-man`，U-Net 训练标签来源）、机器图（`-mac`），
以及 6 张样本的人工 / 机器两版 WinRHIZO 端到端扫描数据。
这是项目里最宝贵的资产，也是当前最大的瓶颈。

U-Net 训练集目前只有 **12 个人工标注样本**，按整图切分 train 9 / val 3（同一张图的 patch 不跨集合）。


## 技术路线一：经典规则管线

`code/rootseg_common.py` 是唯一实现（两个数据集共用，保证口径一致），`code/residue.py` 负责残留清理，
`code/borderclean.py` 负责扫描边框清理。

```
RGB 原图
 ├─ 洪水填充（容差 20，含内部亮点种子）→ 背景
 ├─ 前景 ∩ 够暗 ∩（褐色饱和 或 管状响应）→ 根芯
 ├─ 形状救回：细长的浅色结构也判根（关键，救淡细根）
 ├─ 连通块过滤（面积 / 灰度 / 饱和度），被救回的块豁免颜色判据
 ├─ 贴边伪影剔除（EDGE_KILL，见"已知问题"）
 ├─ 放大回全分辨率（平滑插值 + 阈值 0.5）
 ├─ 收边(腐蚀1px) → 接断点(闭2) → 去毛刺(开1)
 └─ 二值化：根 = 0 黑，背景 = 255 白
```

冻结参数：`FEAT_LONG=3000`、`HALO_GROW=0`、`SHRINK_PX=1`、`SMOOTH_OPEN_PX=1`、
`BRIDGE_CLOSE_PX=2`、`FLOOD_TOL=20`。

特征尺度是这条路线的命门：7019 px 的图缩到 1400 px 时，3 px 宽的细根只剩 0.7 px，
管状响应基本看不见。提到 3000 px 后掩膜 IoU 从 0.607 升到 0.669，代价是单张约 14 秒。

## 技术路线二：U-Net

| 项 | 值 |
|---|---|
| 结构 | `smp.Unet(encoder_name="resnet34")`，24.4M 参数 |
| 输入 | 512×512 patch，Dice + BCE 损失，AMP |
| 增强 | 水平 / 垂直翻转、90° 旋转、±20% 亮度抖动 |
| 训练 | AdamW + 余弦退火，40 轮约 4.8 s/轮，峰值显存 2.1 GB，seed 42 |
| 最佳 val Dice | **0.9004**（186 train patch / 68 val patch） |
| 权重 | `outputs/训练/best_unet.pt`（93 MB，未入库） |
| 推理 | 512 滑窗 → 边框清理 → 细壁闭合环剔除 → 非根涂白 |

**一个必须记住的教训**：patch 级指标会系统性高估整图效果。
首轮 patch Dice 0.89，整图中位只有 0.53 —— 抽 patch 时优先抽了有内容的区域，
而整图绝大部分是背景，背景区的误检在 patch 指标里完全体现不出来。
换成整图评估后才发现 96% 的误检堆在图像边缘。

根因是**三张训练标签没清扫描黑边**，标签里那圈黑边被当成根，模型于是学会了"深色长条 = 根"。
用 `code/47_auto_clean_borders.py` 自动清理边框后重训，整图 Dice 中位从 0.526 升到 0.845。

## 结果

### 端到端：WinRHIZO 实测（6 张样本，同扫描仪同阈值）

机器图相对人工精修图的偏差，单位为百分比（`-` 表示机器偏小）：

| 样本 | 根总长 | 投影面积 | 表面积 | 平均直径 | 根体积 | 根尖数 | 特征 |
|---|---|---|---|---|---|---|---|
| 28-CL-003 | −0.6 | −8.7 | −8.7 | −8.2 | −16.0 | +82.8 | 根最黑最饱和 |
| 66-003 | **−18.1** | −15.1 | −15.1 | +3.6 | −11.9 | −13.1 | 阴影最重 |
| 126-003 | +4.6 | −2.9 | −2.9 | −7.2 | −9.9 | +40.1 | 根最粗 30 px |
| 134-003 | −0.0 | −8.0 | −8.0 | −8.0 | −15.3 | +23.0 | 根系最密 |
| **G218-001** | **−36.5** | **−40.5** | **−40.5** | −6.2 | **−44.4** | −47.2 | **根最淡（灰度 163）** |
| 7-003 | +7.2 | −2.2 | −2.2 | −8.8 | −10.8 | +88.0 | 修得最细致 |
| **中位** | **−0.3** | **−8.3** | **−8.3** | **−7.6** | **−13.6** | — | |

两个结论：一是**除根总长外全部系统性偏小**，说明收边（1 px 腐蚀）收过头了，
而整数像素的收边没有中间档可调；二是 **G218-001 一张拖垮全局**，
极淡细根（细侧根灰度约 210，几乎与纸同色）在核心判据那一层就漏了。

### 杉阔混交林：U-Net vs CV（117 张可比样本）

| 指标 | CV | U-Net |
|---|---|---|
| 根占比中位 | 0.457% | **0.590%** |

## 已知问题

### 1. `EDGE_KILL` 会误杀真根（未修复）

`rootseg_common.py` 判"贴边 **且** 外接框跨度 ≥ 画幅 25% → 扫描仪边带，删除"，
这条规则会连顶到画面边缘的长根一起删掉。

铁证 `杉阔混交林/F补/23-B-GG-002`：连通块过滤后检出 **154,341 px** 的完整根，
贴边剔除后只剩 **4,718 px**。三个数据集都受影响，抽样 40 张里单张最高被删 42%。

修复方向：把"跨度 ≥ 25%"改成"主体像素落在最外圈窄带内"（`borderclean.py` 用的就是更安全的双重判据）。

### 2. U-Net 覆盖不全

数据集1 缺 80 张、数据集2 缺 26 张。那 180 张原本是"预标注候选"（给人工标注做初稿），
不是正式全量交付。要补齐需再跑 106 张。

### 3. 极淡细根漏检

代表就是 G218-001（根总长 −36.5%）。卡在核心判据处：淡细根的褐色饱和度和管状响应都弱，
3000 px 特征尺度下 3 px 宽的细根只剩 1.3 px。

### 4. 一套全局参数打天下

实测单张掩膜面积倍数在 0.564–1.381 之间摆动，且 G218-001 与 7-003 的需求**相反**
（前者要更灵敏、后者要更收缩）。逐图自适应正是 U-Net 路线要解决的问题。

### 5. 分析区不一致（未排查的混杂因素）

WinRHIZO 自动判定的分析区在两版图上不一致（如 28-CL-003：人工 184 cm² vs 机器 70 cm²），
因为机器图是纯白背景。比较端到端指标时这一项会混进来。

### 6. 当前最大瓶颈：标注只有 12 张

目标量是 150–200 张。下一步的关键动作是扩充并清理人工标注，而不是继续调规则阈值。

## 口径与约定

**着色方式不同，别直接比灰度值。** CV 产出是纯黑白二值（2 个灰阶，根 = 0）；
U-Net 产出是保留原色的白底图（约 246 个灰阶，根保留褐色）。两者表达同一件事，
做像素比对时统一按**"非白像素"**统计。

**文件名后缀不统一（刻意保留）。** 杉阔混交林是 `<样本>-mac.tif`，数据集1/2 是 `<样本>-unet.tif`。
改名会破坏 `batch_unet_report.csv` 等记录，按样本名匹配即可。

**dpi 换算。** 管线统一归一到 600 dpi，按 **1 px = 0.042333 mm** 换算。
原始文件有差异（0814 的 10 张是 720 dpi；`G218-002` 幅面异常），逐张数值见 `outputs/阶段一/measure_lookup.csv`。

**重复样本。** `杉阔混交林/9.8校准` 那 35 张与 `数据集2/9.8校准` 逐字节相同（MD5 一致）；
`杉阔混交林/F` 里另有 34 张与 `9.8校准` 同名（同一物理样本的旋转版）。做统计时注意别重复计数。

**命名约定。** 输出用 `<样本>-man.tif`（人工修图）/ `<样本>-mac.tif`（机器修图）/
`<样本>-unet.tif`（U-Net 候选）；标注打版本号（`mask_v1`、`mask_v2`…），旧版本一律保留。

**工程坑。** Python 打印中文到 Windows 控制台会抛 `UnicodeEncodeError`，脚本开头需
`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`；`.ps1` 里不要写中文字面量
（PowerShell 按 GBK 读脚本文件）；`cv2.resize` 的插值结果范围是 [0,1]，阈值必须 `> 0.5` 而不是 `> 127`。
