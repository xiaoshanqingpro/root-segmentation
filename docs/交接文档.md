## 0. 一句话说清这个项目在干什么

把根系**扫描图**里的背景干扰（水渍、阴影、反光、扫描仪黑边）去掉，只留根系，
输出白底根图喂给 **WinRHIZO** 测 **根总长 / 表面积 / 根体积 / 平均直径**。

用户是林学方向的研究生，最终要拿这套流程处理几百张根系扫描图出论文数据。

### 1.1 现状数据：6 张样本的端到端实测（这是最硬的证据）

### 1.2 三个问题（按严重程度）

**问题一：机器修图现在系统性偏小**

除根总长外，**全部为负**：表面积 −8.3%、根体积 −13.6%、平均直径 −7.6%。

> 注意方向已经反过来了：优化前是"面积偏大 48%"，加了收边 1px 之后变成"偏小"。
> **说明收边收过头了**，但收边量是整数像素（1px 一个台阶），没有中间档可调。

**问题二：G218-001 一张毁掉全局（极淡细根）**

它是"根最淡"那张（根灰度 163，细侧根灰度约 210，几乎与纸同色）：
**根总长 −36.5%、表面积 −40.5%、根体积 −44.4%**。

根因已定位到代码级：
- 洪水填充容差 20 与用户口径一致，**不是**它的问题（实测保留 94.9%）；
- 卡在"核心判据"（要求褐色饱和 或 管状响应），淡细根两者都弱；
- "形状救回"逻辑本该救它，但被后面的"块均灰度>185 判背景"反杀（已修，仍不够）；
- 3000px 特征尺度下，3px 宽细根只剩 1.3px，Frangi 仍偏弱。

**问题三：全局固定参数 vs 图像巨大差异**

| 维度 | 跨度 |
|---|---|
| 根颜色（灰度） | 62（近黑）～ 163（极淡） |
| 根粗细 | 10 px ～ 30 px |
| 阴影/水渍 | 1% ～ 14% |
| 根系密度（前景） | 2% ～ 23% |

而现在是**一套全局参数打天下**。实测掩膜面积倍数中位 0.996 看着完美，
但单张在 **0.564～1.381** 之间摆，而且 G218-001 与 7-003 的需求**相反**
（前者要更灵敏、后者要更收缩）——**一套参数必然按下葫芦浮起瓢，这已被证明。**

### 1.3 ✅ 结论与建议

**继续手工调规则的边际收益已趋零。应该转向学习型方法（U-Net 语义分割）。**

理由：
1. 规则无法逐图自适应，而这正是误差的主要来源；
2. 已有 6 张人工真值，可以启动小样本训练；
3. 任务书原始规划（见早期 `docs\阶段二_启动说明.md`）就是训 U-Net，经典管线只是"预标注工具"。

**接手后第一个建议**：不要再调 `rootseg_common.py` 的阈值参数。
先用现有 6 张数据训练一版 U-Net，看它能不能同时压住 G218-001 和 7-003 这两头。

## 5. 核心实现：`code\rootseg_common.py`

**这是唯一需要改的地方。** 数据集1 和数据集2 共用它，保证口径一致。

### 当前参数（已优化，但见 §1）

```python
FLOOD_TOL = 20          # 洪水填充容差 = 用户油漆桶口径，★不要改★
FEAT_LONG = 3000        # 特征尺度长边（原 1600；提到 3000 后掩膜 IoU 0.607→0.669）
DARK_DROP = 12          # 比局部背景暗多少算"非背景"
SAT_ROOT = 0.10         # 褐色饱和度阈值
FRANGI_TUB = 0.20       # 管状响应阈值
GRAY_TUB = 220          # 管状判据的暗度上限（原 170，放宽以救淡细根）
HALO_GROW = 0           # 贴根半影外扩 ← 实测该参数无效，已关闭
SHRINK_PX = 1           # 全分辨率收边腐蚀半径 ← 见 §1.2 问题一
SMOOTH_OPEN_PX = 1      # 去毛刺
BRIDGE_CLOSE_PX = 2     # 接断点
MIN_AREA_FEAT = 25      # 最小连通块（特征尺度 px）
GRAY_COMP_MAX = 185     # 块均灰度上限（灰块过滤）
SAT_COMP_MIN = 0.045    # 块均饱和度下限
PALE_RESCUE = True      # 形状救回：细长的浅色根仍判根
PALE_DROP = 6           # 救回路径专用的暗度门槛（比 DARK_DROP 更敏感）
```

### 管线流程

```
RGB 图
 └─ 边界+内部亮点种子洪水填充（容差20）→ 背景
 └─ 前景 ∩ 够暗 ∩ (褐色饱和 或 管状且够暗) → 根芯
 └─ **形状救回**：细长(√面积/半宽>5)的浅色结构也判根  ← 关键
 └─ 连通块过滤（面积/灰度/饱和度），**被救回的块豁免颜色判据**  ← 踩过坑
 └─ 贴边伪影剔除（贴边+跨度大 或 贴边+偏亮）
 └─ 放大回全分辨率（平滑插值 + 阈值 0.5）
 └─ 收边(腐蚀) → 接断点(闭运算) → 去毛刺(开运算)
 └─ 白底化：非根 → 纯白(255,255,255)，根保留原色
```

### 调用方式

```python
import rootseg_common as R
root, fg, info = R.extract_root(rgb, return_maps=True)
out = R.whiten(rgb, root)
```

多进程并行（本机 32 逻辑核，但**可用内存仅 ~4.6 GB，并行度别超过 8**）：
```python
R.run_parallel(tasks, workers=8, label="任务名")
```

## 6. ★ 必须知道的坑（都是踩过的）

### 数据层面

1. **数据集2 是横向 7019×4962，数据集1 是纵向 4962×7019**，差 90°。用户已明确**不转朝向**。
2. **数据集2 四边有扫描仪黑边**，洪水填充必须补"内部亮点种子"，否则整张图会被判成前景。已在代码里。
3. **`采样数据` 文件夹只读！** 用户明确要求不要修改。用户的 `9.9改\` 是手工在制品，**碰都不要碰**。
4. **`9.15` 有两份完全重复的拷贝**（`图片\9.15\` 与 `图片\多样性林\9.15\`，30 张 MD5 相同）。
   已决定"读取时按 MD5 去重"，`25_process_dataset2.py` 已实现。
5. **数据集2 的 9.9 与 9.9改 同名但内容不同**。已决定：用 9.9 原图，9.9改 排除。
6. **人工真值有灰色噪点**（用户提醒）。实测灰噪占比：G218-001 最多 0.250%，其余 0.001~0.074%。
   二值化统一用**阈值 210**（敏感性分析选出，见 `outputs\二值化分析\`）。
7. **WinRHIZO 的分析区（AnalysedRegionArea）在两版图上不一致**（如 28-CL-003：人工 184 cm² vs 机器 70 cm²）。
   因为机器图是纯白背景，软件自动判定的分析区变了。**这是个尚未排查的混杂因素。**

### 方法层面（都失败过，别重复）

| 尝试 | 结果 |
|---|---|
| 整图丢给 SAM | **CUDA OOM**（SAM 要把掩膜上采样回 4900×6900，单批要 24.66 GiB ≫ 8 GiB 显存） |
| SAM2 | **装不上**：PyPI 无 Windows 预编译轮子 + 本机无 MSVC 工具链 |
| 让 SAM 判"阴影"类 | SAM 把纸面背景整块判成阴影，还留下**窗口形状的方块伪影** |
| "细结构高对比"规则去水泡线 | **误删真根**，用户复核后作废 |
| 闭合环判据（3 个版本） | 特征尺度上细线碎成上千块，**拓扑判据不可靠** |
| 贴根半影外扩 | `HALO_GROW` 0 和 1 结果完全相同，**实测无效** |
| 简单阈值 / 照度校正 | 阴影误判为根 21%→17%，**经典方法不够** |

### 工程层面

8. **特征尺度至关重要**：7019px 图缩到 1400px 时 3px 宽细根只剩 0.7px，Frangi 看不见。
   提到 3000px 后掩膜 IoU 0.607→0.669。**代价：单张约 14s（原 3.3s）。**
9. **`cv2.resize` 插值 + 阈值有陷阱**：`core` 是 0/1 的 uint8，插值后范围是 [0,1]，
   阈值必须 `> 0.5` 而不是 `> 127`（踩过，导致掩膜全空）。
10. **`R.run_parallel` 用的是内置的 `process_file`**，传自定义任务函数时不要用它，会跑错。
11. **PowerShell 脚本文件会被按 GBK 读**：`.ps1` 里**不要写中文字面量**，中文路径从命令行参数传。
12. **Python 输出中文到控制台会崩**：Windows 控制台默认 GBK，打印 `²` `³` 会抛
    `UnicodeEncodeError`。脚本开头加 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。
13. **`测试数据.TXT` 是 GBK 编码、制表符分隔**，列名在含 `SoilVol(m3)` 的那一行。

## 9. 建议的接手路线

### 第一步：先解决"系统性偏小"（半天，见效最快）

机器修图现在表面积 −8.3%、根体积 −13.6%、直径 −7.6%，**方向一致**。
先试把 `SHRINK_PX` 从 1 降到 0，或改用"按宽度比例收边"而非统一腐蚀，
重新出图送扫，看能否把偏差拉回 0 附近。

同时排查 **分析区不一致**（§6 第 7 条）这个混杂因素。

### 第二步：上 U-Net（主线，最该做的）

- `segmentation-models-pytorch` 已装好，用 `Unet(encoder_name="resnet34")`
- 输入 512×512 patch；损失 Dice + CE；三分类（根/阴影/背景）
- 增强：水平/垂直翻转、90° 旋转、±20% 亮度抖动
- 输出 mask 命名 `<原文件名>_mask.png`，与原图同分辨率
- **必须按整图划分 train/val/test**（同一张图的 patch 不能跨集合）
- 8G 显存，512 patch + resnet34，batch size 试 4~8
- 6 张起步偏少，建议先做**留一交叉验证**（leave-one-out），看模型能不能同时压住 G218-001 和 7-003

### 第三步：扩真值 + 端到端验证

让用户再精修 **15~20 张**（重点补"极淡细根"这类），留 5 张做独立验证集（不参与训练）。
每轮模型出图 → 用户送 WinRHIZO 扫 → 比四项指标。

### 第四步：全量推理与质检

滑窗重叠推理，输出全分辨率对齐的 mask，随机抽 5% 做质检。
