## 2. ⚠️ 问题一：`9.15` 整份重复（30 张逐字节相同）

```
图片\9.15\*.jpg   ==   图片\多样性林\9.15\*.jpg
```

30 个文件 **MD5 完全相同**，是彻底的重复拷贝（约 580 MB）。

**风险**：如果两份都进数据集，**同一张图会同时出现在训练集和验证集**——
这是最典型的 train/val 泄漏，会让验证指标虚高、模型实际泛化能力被高估。

**建议**：只保留一份。推荐保留 `图片\多样性林\9.15\`（与其它日期子集放在一起，层级一致），
删掉 `图片\9.15\`。

**建议（需你定）**：

## 4. 朝向问题：第二数据集比第一数据集转了 90°

| 数据集 | 尺寸 | 朝向 |
|---|---|---|
| 第一数据集（扫描\图片） | 4962×7019 | **纵向** |
| 第二数据集（采样数据\图片） | 7019×4962 | **横向** |

dpi 相同（都是 600），所以**物理尺寸一致，只是拍摄/摆放方向不同**。

**影响**：
- 训练 patch 提取、数据增强（翻转/旋转）**不受影响**；
- 但如果要沿用第一数据集的**裁边参数**，必须换成"左右→上下"的对应边（伪影带方向也转了 90°）；
- WinRHIZO 之类的测量流程一般不在乎朝向。

**建议**：为统一管理，处理时把第二数据集**顺时针/逆时针转 90° 成纵向**，
输出时保持 600 dpi 不变。这样两批数据在尺寸、朝向、命名上完全一致，后续划分 train/val/test 不会踩坑。

   —— 看命名是一套图片 OCR → Excel 流程，与根系分割无关，处理时只取 `图片\` 子目录。
