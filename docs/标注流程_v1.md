# 标注流程（v1）：机器预标注 → 人工只做检查

生效日期：2026-09-23 ｜ 工具：`code/49_preannotate.py`

---

## 0. 一句话流程

```
原图 ──[U-Net 预标注]──> 机器候选 ──[边框/细线自动清理]──> <样本>-mac.tif
                                                              │
                                                              人工检查、修正
                                                              ↓
                                                        <样本>-man.tif
                                                              │
                                                    进训练集 → 重训 → 回灌
```

**人工只需要"检查+修正"，不需要从零画。**

---

## 1. 命令

```powershell
cd C:\Users\<用户名>\Desktop\扫描\根系分割项目

# 看会处理哪些图（不实际跑）
python code\49_preannotate.py --src "C:\Users\<用户名>\Desktop\扫描\原始图片" --list

# 正式生成候选
python code\49_preannotate.py --src "C:\Users\<用户名>\Desktop\扫描\原始图片" `
                              --out "outputs\预标注候选"

# 也可以只跑一个文件 / 限定数量
python code\49_preannotate.py --src "<某个tif>" --out "outputs\预标注候选"
python code\49_preannotate.py --src "<某个目录>" --limit 10 --out "outputs\预标注候选"
```

## 2. 机器做的三步

| 步骤 | 做什么 | 实现 |
|---|---|---|
| ① U-Net 推理 | 512 滑窗、384 步长、重叠区概率取平均、阈值 0.5 | `outputs/训练/best_unet.pt` |
| ② 边框自动清理 | 扫描仪**深色黑边** + **浅色纸边/盖板边**，只动贴到最外缘的连通块 | `code/borderclean.py` |
| ③ 细壁闭合环剔除 | 水渍水泡反光形成的**闭合细线**（逐级腐蚀测壁厚定位） | `49_preannotate.py` |

> 没有 U-Net 权重时会自动回退到经典规则管线 `rootseg_common.py`，流程不中断。

## 3. 产出

```
outputs\预标注候选\
├─ <样本>-mac.tif            机器候选（600 dpi，根保留原色、非根纯白）
├─ _preview\<样本>_cand.png   预览图（人工先看这个快速过一遍）
├─ candidates.csv            清单：逐张根占比 / 剔除的边框像素 / 剔除的细线环数
└─ preannotate.log           运行日志
```

**不覆盖任何原始文件。**

## 4. 人工怎么检查（建议顺序）

1. 先翻 `_preview\*.png` —— 一张图扫一眼，**只挑有问题的**
2. 有问题的那几张，打开同名 `<样本>-mac.tif` 在 Photoshop 里修：
   - 漏掉的根 → 补
   - 多出来的灰块 / 细线 / 边框残留 → 涂白
   - 存为 `<样本>-man.tif`（**-man 后缀是人工标注的约定**）
3. 没问题的图也要**另存为 `-man.tif`**（可以直接复制 mac 版），保证"每个进训练集的样本都有 -man"

## 5. 命名约定（重要）

| 后缀 | 含义 | 谁产出 |
|---|---|---|
| 无后缀 | 原图 | 扫描仪 |
| `-mac` | 机器候选 | `49_preannotate.py` |
| `-man` | 人工标注（**训练标签只用这个**） | 人工修正后另存 |

**训练永远只用 `-man`。** 训练和评估必须用同一套标签，否则指标没有意义
（这个坑已经踩过一次：评估时误用未清理的旧 GT，让一张图的 Dice 从 0.792 虚报成 0.575）。

## 6. 扩标注的节奏建议

| 轮次 | 标注量 | 动作 |
|---|---|---|
| 第 1 轮 | 现有 12 → **约 50 张** | 跑预标注 → 人工检查 → 重训，看整图 Dice 是否继续上升 |
| 第 2 轮 | → **约 120 张** | 同上；此时模型应能给出较准的候选，人工只做微调 |
| 第 3 轮 | → **150–200 张**（任务书目标） | 收尾，冻结数据集，划分 train/val/test |

每轮重训后都用 `code/44_infer_unet.py` 看整图指标，并用 12 对 WinRHIZO 端到端数据
（`outputs/误差分析/`）核对**根总长/表面积/根体积**的误差是否收敛。

## 7. 已验证的有效性

清理边框这一件事，就把 U-Net 整图 Dice 中位从 **0.526 提到 0.845**：

| 样本 | 清边框前 | 清边框后 |
|---|---|---|
| 126-003 | 0.526 | **0.964** |
| 66-003 | 0.449 | **0.845** |
| 46-002 | 0.884（虚高） | 0.792（诚实值） |

**结论：标注质量比标注数量影响更大。** 新标注一定要走"机器预标注 + 自动清边框"这条流水线。
