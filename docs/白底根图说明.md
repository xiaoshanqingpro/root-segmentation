### 本轮修掉的两个问题

**问题一（用户反馈）：有灰底残留、有小碎片、非根没全变白，尤其靠近根的灰块。**

根因：判根用 `管状响应(Frangi) 或 褐色饱和`，而 **Frangi 判据缺少"够暗"的约束**——
大块灰底的边界在某个尺度上同样是"脊状"，Frangi 照样亮，于是灰块整块被判成根、保留了原色。
另外面积阈值被 `sc²` 缩放抹平，碎块没清掉。

修法（`code/rootseg_common.py`，两个数据集共用）：
1. 管状判据附加**绝对暗度**约束：`Frangi 高 **且** 灰度 < 170` 才算根
2. 贴根半影外扩只吸收"仍足够暗（<200）"的像素
3. **连通块级过滤**：面积 < 25px、块均灰度 > 185、块均饱和度 < 0.045 的块判背景
4. **形状救回**：颜色不够但**细长**的浅色细根仍判根
   （难点：淡细根与灰块颜色几乎一样，只能靠形状分。用 `√面积/半宽` 度量细长程度，
   细根可达 10 以上，团块只有 ~1.77）
5. 掩膜放大回全分辨率时用**平滑插值再阈值**，消除锯齿

效果：

| 指标（中位） | 修订前 | 修订后 |
|---|---|---|
| 灰底残留（第一数据集） | 15–23% | **3.9%** |
| 灰底残留（第二数据集） | 17–26% | **6.0%** |
| 小碎片个数（第一数据集） | 200–2600 | **9** |
| 小碎片个数（第二数据集） | 169–2656 | **25** |

**问题二（用户反馈）：GPU/CPU 占用都不高，能不能快点。**

原因：脚本原来是**单进程单线程**，本机虽然有 **32 个逻辑核**却只用了一个。
GPU 占用 5% 是正常的——白底化是纯经典 CV 管线（numpy/opencv/skimage），用不到 GPU，
GPU 是留给后续 U-Net 训练的。

修法：改为**多进程并行**（`ProcessPoolExecutor`）。并行度定 8 而非更高，
因为本机可用内存只有约 4.6 GB，每个进程峰值约 400 MB。

效果：

| | 修订前 | 修订后 |
|---|---|---|
| 第一数据集 106 张 | ~13 分钟 | **2.1 分钟** |
| 第二数据集 180 张 | ~18 分钟（实测前 140 张用 166s） | **3.5 分钟** |
| 单张耗时 | 5–8 s | **1.2 s** |

## 2. 判根口径：与你的油漆桶操作完全对齐

你说"用油漆桶工具倒背景时设置的容差为 20"——我就按这个算法实现了：

| 步骤 | 实现 | 对应你的操作 |
|---|---|---|
| 去背景 | **边界种子洪水填充，容差 20**（`cv2.floodFill`，`FIXED_RANGE`） | 油漆桶容差 20 倒背景 |
| 定根 | 前景 ∩（管状响应 或 褐色饱和） | 肉眼判断哪是根 |
| 贴根半影 | 根芯**外扩 ≤6 px（≈0.25 mm）**，与外扩内仍属前景且偏暗的像素合并 | 你说的"半影计入根系、可适当修剪" |
| 去杂物 | 连通块 < 40 px（≈0.07 mm²）判背景 | 灰尘/纤维不画 |
| 兜底 | 判不出来判背景 | 你已接受 |

> **已知取舍**：比背景暗不足 20 灰阶的极淡细根会被洪水填充吸收掉。
> 这是容差 20 本身的特性——你用油漆桶时同样会碰到，属于口径一致而非缺陷。
